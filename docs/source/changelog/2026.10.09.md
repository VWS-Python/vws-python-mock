# 2026.10.09 (2026-10-09)

## Changes

- Make VuMark targets with zero processing time immediately ready for instance generation, even when their last modified timestamp is equal to or ahead of the server clock.
  Targets with positive processing time become ready at their exact completion timestamp. ([#3705](https://github.com/VWS-Python/vws-python-mock/issues/3705))
- Clean up Docker deployment test images and containers even when fixture setup fails partway through. ([#3711](https://github.com/VWS-Python/vws-python-mock/issues/3711))
- Bound Flask health-check HTTP requests to five seconds so an unresponsive server is reported as unhealthy. ([#3712](https://github.com/VWS-Python/vws-python-mock/issues/3712))
- Set `VWS_BASE_URL` in the Docker setup instructions so report download URLs point to the published mock service. ([#3713](https://github.com/VWS-Python/vws-python-mock/issues/3713))
- Wait for Docker test services through their published HTTP ports as well as their native Docker health checks. ([#3714](https://github.com/VWS-Python/vws-python-mock/issues/3714))
- - Document running and building the mock directly with Apple's container CLI using the same images as Docker.
    Support the existing deployment tests through Socktainer's optional Docker API, allow an explicit API version, and bind all test service ports to loopback.
- Publish native Markdown release notes and use the same notes in documentation where available.
